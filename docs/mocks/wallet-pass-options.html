Wallet passes: new designs and how to customise them

Three looks for the Apple Wallet ticket, a redesigned back with real links, and three ways the event page could expose all of it. Everything shown uses keys the installed pass library already supports. Nothing here is built yet.

What Wallet can do that the pass does not use

Today a pass is the band, four colours, a logo, five fields on the front and plain text on the back. The library in the repo (passkit-generator 3.5.7) exposes a lot more, and most of it costs a few lines of pass.json plus somewhere to type it in.

Same event, same AAA ticket, three layouts. Each is a value of one new field on the design, so an event can switch between them and every level inherits as today. Layouts are approximate, as the debugger preview is. Type scales with the holder's text size on the real thing.

Back and beyond

The back, the guide and the lock screen

Shared by all three designs. The back stops being a wall of text: every row that can be tapped is tapped, the line-up comes off the gig's run sheet, and organisers can add their own rows. On iOS 18 the poster layout also gets the event guide and a transfer action.

What gets stored, and what stays automatic

Everything new is more optional fields on the same per-layer design, so an AAA level can set a chin colour and inherit the poster from the event exactly as colours work today. Nothing on this page needs a new table.

Added to the design layer

  • layout BAND, BLUR or POSTER
  • posterImageId, thumbnailImageId
  • logoText
  • headerShade, autoColours, chinHex
  • guide one URL per button, plus venue phone, email, website
  • transfer, openInApp, allowSharing
  • backRows built-in rows on or off, custom rows with label and text, in order
  • nearVenue, radiusM, liveActivity, changeMessages

Derived, no UI

  • Directions link from the venue address
  • Venue coordinates, geocoded on save and stored on the event
  • Line-up and set times from the linked gig's run sheet
  • Grouping by order number, so one order is one stack
  • Semantics: event name, type, venue, performers, admission level, dates
  • Transfer link to the holder's ticket page
  • App link from the App Store id, once there is one

Google Wallet gets the same inputs

Guide links land in the links module, custom back rows in text modules, the poster in the hero image. One design, both wallets. Nothing in the Google class needs a new provisioning step.

To check on a device before committing

  • Poster artwork size and crop. Apple's guide pages do not render without a browser, so the exact pixel size needs confirming from a real pass.
  • Whether Wallet draws a poster chin with the fields or hides the barcode behind a tap.
  • Live activity behaviour on a pass updated mid-night.

Suggested order if all of it is wanted

  • Back of the pass with links and custom rows, logo text, sharing, change messages and the venue location. Every phone benefits and no artwork pipeline changes.
  • Poster layout with the band kept as the fallback, the guide links and transfer. One new image per event.
  • Blur layout, live activity and the app link, which depends on the app being in the store.
