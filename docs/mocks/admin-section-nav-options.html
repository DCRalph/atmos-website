Section navigation for admin pages

The ticketed event page has the only true sub sidebar in the admin: an unstyled 180px column of text buttons that turns into a wrapped row of pills on a phone. The gig editor, link, rental and user pages each do something different with tabs. These are three ways to give every multi-section page one navigation component built from the same primitives as the main sidebar.

Static mocks with fictional event data. The event page is the example; the same component replaces the tab strips elsewhere, shown at the end.

ASection rail

A second column that reads as part of the main sidebar: same surface, same group labels, same 36px icon rows and active state. The rail owns the event context (back link, name, status) so the page heading can drop them. The main sidebar collapses to its icon mode while a rail is present, which is what its existing collapsible setting is for, and the header trigger still expands it.

Phone: the rail becomes a horizontally scrolling chip strip pinned under the page heading, with a divider between groups and the count inside the chip. One row, no wrapping. Cost: a new SectionRail slot in the admin layout that pages register into, plus a sidebar-collapse rule. The biggest change of the three, and the only one that gives the page its full width back without touching the main sidebar.

BInset nav

Stays where it is, inside the page next to the content, but rebuilt from the sidebar primitives: icons, 12px group labels at 70% white, 36px rows, the accent background for the active row, counts in a pill, the amber dot for unsaved sections. Overview moves to the top, ungrouped. Sticky to the Save bar so the two always line up.

COne sidebar
